# VK Role Bot: Distributing Hat

VK-бот распределяющей шляпы для сообщества "Хогвартс Онлайн". Бот принимает пользователей в личных сообщениях сообщества, проводит интерактивное распределение по факультетам, сохраняет результат в SQLite, отправляет лог в служебный чат и поддерживает админские команды для обслуживания базы.

## Что умеет

- проводит сценарий распределения через вопросы с кнопками;
- проверяет возраст VK-страницы перед распределением;
- сохраняет студентов, факультет и баллы по факультетам в SQLite;
- публикует пост о новом студенте на стене сообщества;
- отправляет служебные логи в отдельный чат;
- поддерживает сброс профиля по магическому коду;
- хранит код сброса и приоритеты факультетов в базе;
- позволяет root/админам менять приоритеты факультетов;
- позволяет root менять старост, выгружать отчет XLSX и делать бекап базы;
- поднимает простой health endpoint `/ping` на локальном Express-сервере.

## Требования

- Node.js 16.x;
- npm;
- SQLite, используется через Prisma;
- VK community token;
- включенные сообщения сообщества и Long Poll/API-доступ для бота.

Права токена VK должны покрывать операции, которые бот выполняет: получение информации о группе и администраторах, чтение/обработку сообщений, отправку сообщений, отправку документов и публикацию на стене сообщества.

## Переменные окружения

Создайте `.env` в корне проекта. Пример:

```env
DATABASE_URL="file:./hat.db"
token="vk1.a.your-community-token"
root="123456789"
chat_id="2000000001"
group_id="224622524"
```

Описание:

- `DATABASE_URL` - путь к SQLite-базе для Prisma. При `file:./hat.db` файл будет создан как `prisma/hat.db`.
- `token` - токен сообщества VK.
- `root` - числовой VK ID главного администратора бота.
- `chat_id` - peer ID служебного чата для логов.
- `group_id` - ID сообщества без минуса. Можно оставить пустым: бот умеет определять ID по токену и использует это значение как fallback/проверку.

Файл `.env` не коммитится.

## Установка

```bash
npm install
```

Подготовьте `.env`, затем примените миграции:

```bash
npx prisma migrate deploy
```

Сборка также генерирует Prisma Client:

```bash
npm run build
```

## Запуск

Для разработки:

```bash
npm run dev
```

Для обычного запуска:

```bash
npm start
```

`npm start` пересобирает проект и запускает `build/index.js`.

Health endpoint после запуска:

```text
http://localhost:3004/ping
```

## Скрипты

- `npm run generate` - генерирует Prisma Client.
- `npm run build` - генерирует Prisma Client, очищает `build/` и компилирует TypeScript.
- `npm start` - собирает проект и запускает собранный бот.
- `npm run dev` - запускает TypeScript-версию через `ts-node-dev`.
- `npm run pm2` - текущий dev-запуск через `ts-node-dev`; для production PM2 лучше отдельно настроить запуск `npm start` или `node build/index.js`.

## База данных

Prisma schema находится в `prisma/schema.prisma`.

Основные модели:

- `User` - распределенные пользователи и результаты ответов;
- `Headman` - ссылки/имена старост факультетов;
- `Config` - приоритеты факультетов и код сброса профиля.

Миграции лежат в `prisma/migrations`. Локальные SQLite-файлы (`prisma/hat.db`, journal-файлы) игнорируются git.

## Команды бота

- `!протего <код>` - изменить код сброса профиля. Доступно root и администраторам сообщества.
- `!приоритеты` - изменить приоритеты факультетов. Доступно root и администраторам сообщества.
- `!староста` - изменить старосту факультета. Доступно только root.
- `!бекап` - отправить бекап базы. Доступно только root.
- `енотик` - сформировать и отправить XLSX-отчет по студентам.

Обычный пользователь проходит распределение через личные сообщения сообщества. Если пользователь уже распределен, бот показывает меню с вариантами повторного входа, возврата в школу и сброса профиля.

## Важная заметка про новые VK-страницы

После перехода на новые версии библиотек новые VK-страницы могут приходить в `vk-io` как `peerType: "chat"`, хотя фактически это личная переписка с пользователем. Поэтому обработчик не должен слепо игнорировать все события с `peerType === "chat"`.

В текущей логике настоящая беседа отсекается только когда `peerType === "chat"` и `peerId !== senderId`. Это позволяет не отвечать в групповые беседы, но продолжать обслуживать новые личные страницы VK.

## Деплой

Минимальный порядок на сервере:

```bash
npm install
# создать .env
npx prisma migrate deploy
npm run build
npm start
```

Для process manager можно использовать PM2, но текущий `ecosystem.config.js` запускает `npm run dev`. Для production-режима обычно лучше настроить PM2 на `node build/index.js` после `npm run build`.
